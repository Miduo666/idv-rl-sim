## 一、结构：不是"4 分支 × 8 槽位"

旧记录猜的是 `1-8 / 9-16 / 17-24 / 25-32` 四段 + `33+` 散号。**实际结构由 `layer` / `node_seq` 定义**：

```
layer 1  分支根      id 1, 9, 17, 25              (每边 4 个根)
layer 2  第二层      每根 3 个   (node_seq 1/2/3)
layer 3  第三层      每根 3 个   (node_seq 1/2/3) + id 33~40 是 node_seq 4/5 的额外节点
layer 4  终端天赋    id 8, 16, 24, 32             ← 四个"大天赋"
```

`pre_genius` 给出前置依赖（如 `civilian_genius[26].pre_genius = ((25,1),)`，
`[8].pre_genius = ((5,3),)`），**整棵树的拓扑都在表里**。

`lv` 列是该天赋可选等级：`[1]` = 只有一级，`[1,2,3]` = 三级可加点。
这解释了活体 `genius_id_lv_lst` 里为什么等级只出现 1 和 3。

## 二、两套编号：天赋 id ↔ 被动技能 id

```
genius id  --passive_skill_id_lv-->  passive skill id  --> ability_used / passive_skill_dct
    26                ((102,1),)              102              {102: True}
```

- `genius_id_lv_lst`（单位属性）用的是**天赋 id**
- `ability.passive_skill_dct` / `ability_used` 用的是**被动技能 id**
- 一个天赋可能展开成**多个**被动技能（如求生者 32 → `[263, 259, 260]`，9 → `[125, 149]`）

⚠️ **`name_tid` 里的数字既不是天赋 id 也不一定是 psv id**（psv `121` 的 `name_tid`
是 `TID_HUMAN_NAME_145_LV1`）。**别自己拼 TID 字符串**，必须走
`get_passive_skill_data_from_id_lv()` 拿 `name_tid` —— 我拼过一次，把
求生者 21/27、14/36 全标反了。
